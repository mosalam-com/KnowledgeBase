# Checklist تسليم العميل (Onboarding)

> المسار الكامل من استلام الطلب حتى التسليم والتسليم التشغيلي — طبعة قابلة للتتبع في كل عقد جديد.
> يربط `operations/processes.md` (سير العمل) بملفات الخدمات والعقود.

## 1) استلام الطلب
- [ ] استلام الطلب/العميل (إيميل أو واتساب أو مكالمة) وتسجيله — القناة والتاريخ.
- [ ] مدارة بيانات العميل (اسم، جهة، بريد، تليفون) + تحديد الخدمة/الخطة المطلوبة.
- [ ] إرسال العرض/العقد للمراجعة (من `pricing/contracts/` حسب النوع).

## 2) الموافقة والعقد
- [ ] موافقة العميل على العقد والأسعار (موقعاً حسب صيغة العقد).
- [ ] اتفاقية مستوى الخدمة (SLA) موقتة — `policies/sla-clause.md`.
- [ ] توثيق الأذونات: موافقة استخدام اسم العميل تسويقياً (انظر `customers/testimonials.md`).

## 3) تجهيز الحل تقنياً
- [ ] إنشاء حساب/سيرفر/حاوية حسب الخطة (`services/hosting.md`، `services/vps.md`،...).
- [ ] تكوين الشبكة والعزل (bridges/NAT/Docker) حسب `engineering/*`.
- [ ] تشغيل النسخ الاحتياطي اليومي (off-site) قبل التسليم — `engineering/backup-restore/`.
- [ ] ضبط الدومين/SSL (نطاق العميل + شهادة) — ربط إلى `pricing/assets.md`.

## 4) النقل والتركيب
- [ ] ترحيل الموقع/البيانات مجاناً (لو المعمول به) مطابق لمواصفات الخطة.
- [ ] تركيب التطبيقات المطلوبة (WordPress/Odoo/ERP/… حسب الخدمة).
- [ ] اختبار: تحميل الموقع، إرسال/استقبال إيميل، أداء أساسي.

## 5) التسليم
- [ ] تسليم بيانات الدخول (لو Unmanaged/Root أو لوحة العميل) عبر القناة الآمنة.
- [ ] شرح قنوات الدعم (نظام التذاكر) والمسؤوليات (Terms/AUP).
- [ ] رفع الفاتورة الأولى وتأكيد طريقة/موعد الدفع.
- [ ] إضافة العميل إلى جدول المتابعة/المراقبة (انظر `engineering/monitoring/monitoring-checklist.md`).

## 6) ما بعد التسليم (الأسبوع الأول)
- [ ] متابعة أول أسبوع: استقرار، أخطاء، رضا العميل.
- [ ] تسجيل أي مشكلة في `engineering/troubleshooting/` (إن حصلت) + تحديث runbook إن لزم.
- [ ] تحديث سجل الأصول (`pricing/assets.md`) بالدومين/الشهادة/الحصة الجديدة.

## ملاحظات
- هذه القائمة مصدرها `operations/processes.md` (سير العمل الأساسي) — أي تعديل في الإجراءات هنا يُحدّث في العمليات أيضاً.
