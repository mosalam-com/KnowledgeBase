# تشخيص المشاكل والحلول (Troubleshooting)

مرجع موحّد لكل مشكلة تقنية صادفتنا، **بما فيها سببها الجذري والحل المنفذ** — بحيث:
1. تكون مرجعا نعود إليه عند تكرار المشكلة بعد أيام أو أشهر (لا نعيد الاكتشاف من الصفر).
2. **تغذّي تحسين تصميم الانفراستراكشر**: كل مشكلة متكررة تكشف ثغرة في التصميم تُعالج بشكل جذري.
3. **تغذّي المراقبة (Monitoring)**: كل مشكلة توضح لك ما الذي كان يجب مراقبته لرصدها مبكرا قبل أن يشتكي العميل.

## كيف تستخدمه
- **ملف لكل مشكلة** باسم وصفي إنجليزي (مثال: `vm-no-internet.md`) — انسخ `00-template.md` لكل مشكلة جديدة.
- املأ كل الأقسام، خصوصا **السبب الجذري** و **تحسين التصميم/المراقبة** (لا تتركهما — هما القيمة الحقيقية لهذا المجلد).
- ربط المشكلة بالملفات التقنية ذات الصلة (في `networking/`، `infrastructure/`...) عبر رابط، والعكس صحيح — كل ملف تقني يشمل جدول أخطاء شائعة مرتبطة بحالات هنا.
- لا تحذف أي حالة محلولة — حتى المحلولة القديمة مرجع لتفادي تكرارها.

## تدفق التحسين (الحلقة)
```
مشكلة → توثيق (هنا) → تحسين تصميم/إعدادات → إضافة مراقبة مبكرة → منع التكرار
```
- **السبب + الوقاية** → يتحولان إلى قاعدة أو runbook في `engineering/` (منع الوقوع أصلا).
- **القسم "تحسين المراقبة"** → يتحول إلى تنبيه/متر أو شيك ليست في خطط المراقبة (Prometheus/Grafana/اختبارات دورية).
- مراجع دورية: كل مراجعة للبنية تبدأ بقراءة حالات هذا المجلد.
